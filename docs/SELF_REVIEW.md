# 자체 점검 기록

점검일: 2026-10-26. 코드 검토, 수정 전 실패 재현, 회귀 검증, 실제 Windows 예약 실행, 개인정보 검사를 수행했습니다. 실제 S4 진입과 PC 종료는 실행하지 않았습니다.

## 수정한 문제

| 문제 | 재현과 영향 | 수정 |
| --- | --- | --- |
| 미디어 초기화보다 늦은 자동 종료 준비 | 초기화 도중 입력한 뒤 5분 이상 입력이 없으면 사용 사실을 놓치거나, 초기화 중 취소한 종료가 다시 예약될 수 있었음 | 입력 기준과 종료 상태를 재생 전에 준비. 초기화 중 알람 정지도 일관된 상태를 유지하도록 처리 |
| 정지 후 지연 재생 시작 | 종료 준비의 UI 알림에서 정지해도 이후 재생 시작에 도달할 수 있음 | 동일 예약이 여전히 울림 상태인지 확인한 다음 재생 요청 |
| 취소 실패를 성공으로 표시 | 예약 JSON을 읽기 잠금하거나 작업 삭제 오류를 주입하면 실패를 로그에만 기록. 파일 저장 실패 뒤 취소 재시도도 저장을 건너뜀 | 파일 저장과 작업 삭제 결과를 구분하여 표시하고 재시도 허용. 재시작 후 취소 유지 검증 |
| 배포 ZIP에 디버그 심볼 포함 | 이전 게시 폴더에 소스 경로가 포함될 수 있는 앱 PDB가 존재. Git에서는 제외되지만 배포 ZIP에는 들어갔음 | 배포 빌드에서 심볼 생성을 끄고 이전 앱 PDB도 제거. ZIP 파일 목록 확인 |

재생 초기화 관련 회귀 사례 3개는 수정 전 실패했고 수정 후 통과했습니다. 정지 후 지연 시작 방지 1개를 추가했습니다. 취소 오류/재시도 사례 3개도 수정 전 실패, 수정 후 통과했습니다. 디스크 접근 실패를 강제로 성공 처리할 수는 없으므로 취소 상태 저장 실패 시 앱을 닫기 전에 재시도해야 합니다.

앱 시작 로그에 프로세스 ID를 추가해 해당 테스트 프로필의 GUI만 식별했습니다. 로그는 배포/커밋 대상에서 제외합니다.

## 검증 결과

- Release 솔루션 빌드: 경고 0, 오류 0.
- 기본 검증 53개 전부 통과. YouTube 성공 시 로컬 억제, 실패 시 플레이어를 닫고 로컬 시작, 늦은 이벤트/정지, 사용자 입력 보호와 카운트다운 취소 포함.
- 실제 Task Scheduler 등록·조회·삭제, 예약 실행기와 GUI 수명 분리, 창 종료 뒤 미래 예약 유지와 재실행: 통과. 전용 임시 작업은 삭제.
- 실제 WebView2 Runtime/HTML/메시지 연결과 배타적 전환: 통과. YouTube API 응답은 모의 응답이며 실제 YouTube 음원 검증은 아님.
- 전체 통합 검증: **56개 통과, 1개 실패**. 음소거 WPF PCM 출력 검증은 `0xC00D11BA`로 실패. 실패를 숨기지 않고 종료 코드 1 반환.
- 오디오 서비스는 실행 중이지만 점검 프로세스의 출력 장치 수는 0. 물리 PC 전체의 장치 상태를 단정할 수 없으며 실제 사용자 환경의 스피커/이어폰 출력 확인 필요.
- 공개 소스의 비밀 값·개인 경로 패턴 및 생성 파일 제외 검사 수행. 계정/전송 보호는 지정한 개인 계정과 원격 저장소만 허용.

## 남은 실제 확인

실제 MP3/YouTube 음원, 잠긴 화면에서의 소리, 물리 S4 복귀, 업데이트 재부팅 후 로그인 복구, 최종 Windows 정상 종료는 미검증입니다. Windows API/예약 설정 검증만으로 하드웨어 Wake와 소리 출력을 보증할 수 없습니다. [README 테스트 순서](../README.md#테스트)와 [상세 결과](VALIDATION.md)를 참고하세요.
