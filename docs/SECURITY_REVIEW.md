# 커밋 전 개인정보·보안 점검

대상 저장소: `JaehongLIM2/alarm_program`. 최근 점검일: 2026-10-27.

## 게시 대상 점검

- Git이 게시 대상으로 열거한 소스·문서·빌드 스크립트를 검사합니다. 실제 값은 출력하지 않고 문제가 있는 파일과 규칙만 보고합니다.
- 개인 키, 주요 서비스 토큰, URL 내 비밀번호, 개인 Windows 프로필 경로, 머신 SID, 소스에 들어간 개인 메일, 명시적인 인증 값 대입 패턴을 검사합니다.
- 소스 점검에서 일치하는 비밀 값이나 개인 PC 경로는 발견되지 않았습니다. 예제의 일반적인 테스트 경로는 실제 사용자 경로가 아닙니다.
- 빌드/배포 파일, PDB, 테스트 프로필, 로그, MP3/WAV, 사용자 설정 JSON, WebView2 프로필/캐시와 생성된 플레이어 페이지, SSH/AWS/개발 도구 설정, 환경 변수 파일, 인증서·키 파일은 `.gitignore`와 점검기로 제외합니다.
- 실제 작성자 이메일은 Git 로컬 설정과 무시되는 `.git-identity.local.json`에만 둡니다. **사용자가 지정한 이메일은 커밋의 author/committer 메타데이터에는 포함됩니다.** 원치 않으면 커밋 전 GitHub의 noreply 주소로 바꿔야 합니다.
- 문서에는 통합 테스트 실패 및 실제 S4/종료 미검증 사실을 유지했습니다.
- `publish.cmd`는 앱 디버그 심볼 생성을 끄고 이전 배포의 앱 PDB도 제거합니다. 배포 ZIP에는 소스 경로가 포함될 수 있는 PDB를 넣지 않습니다.

패턴 점검은 알려지지 않은 모든 비밀 값이나 회사 정보 부재를 보증하지 않습니다. 추가 파일을 넣을 때도 내용을 검토해야 합니다. `pre-commit`에서는 작업 파일 대신 **실제로 스테이징된 내용**을 다시 검사합니다.

현재 게시 대상 **61개 파일의 점검이 통과**했습니다. 이전 점검에서 가짜 토큰과 가짜 개인 경로를 임시 파일에 넣은 음성 테스트는 해당 파일을 차단했고, 제거 후 다시 통과했습니다. 작성자/커미터/원격 주소/전송 설정과 SSH 로그인 계정의 대역을 사용한 **10개 테스트도 통과**한 기록이 있습니다. 이 대역 검증은 실제 SSH 인증이나 푸시 성공을 의미하지는 않습니다. 테스트 자료는 무시되는 `artifacts/guard-tests`에만 있습니다.

.NET 10 전환에서는 프로젝트 전용 SDK와 .NET 8 비교용 소스 복사본을 `artifacts` 안에만 준비했습니다. SDK, 다운로드 메타데이터, 비교용 프로필, 자체 포함 배포본과 ZIP은 Git 게시 대상에서 제외합니다. 실제 마이그레이션 검증은 [NET10_MIGRATION.md](NET10_MIGRATION.md)에 기록했습니다.

단일 EXE 검증으로 생기는 `deployment-check.json`과 `webview2-check` 프로필도 Git에서 제외하고 게시 검사에서 차단합니다. 이 보고서는 실제 실행 경로 등 로컬 정보를 포함합니다. 배포 폴더는 EXE 한 개만 허용하며 PDB·사용자 설정·진단 자료를 동봉하지 않습니다.

내장 YouTube에는 Microsoft 공식 WebView2 패키지 하나를 사용하며 NuGet 소스 매핑과 버전/콘텐츠 해시 잠금 파일을 포함합니다. 앱 전용 프로필을 사용하고 기존 개인/회사 브라우저의 프로필을 가져오지 않습니다. 웹 메시지는 정확한 페이지 출처, 실행별 식별자, 필드 형식을 검사하며 웹에 네이티브 객체를 제공하지 않습니다. 다운로드·임의 외부 페이지 이동·새 창·웹 권한 요청도 허용하지 않습니다.

## 계정 구분

`scripts/publish-personal.cmd`는 다음 순서로 실행됩니다.

1. 지정한 개인 SSH 키로 GitHub에 연결하여 서버 응답이 정확히 `JaehongLIM2`인지 확인합니다. 다른 계정이나 확인 실패 시 커밋 전에 중단합니다.
2. 소유자가 다른 샌드박스 계정인 경우에도 이 프로젝트의 정확한 경로만 게시 프로세스에서 임시로 신뢰합니다. `safe.directory=*`나 전역 예외를 추가하지 않습니다. 이 값은 Git의 자식 프로세스와 훅에도 전달되고 실행 후 복원됩니다. `user.name`, `user.email`, 개인 키 경로, 훅, SSH 전송은 **해당 저장소의 `.git/config`에만** 설정합니다. 회사 계정의 기본 서명이 사용되지 않도록 이 저장소의 자동 커밋·태그 서명은 끕니다.
3. SSH 사용자 설정과 agent의 다른 키, 암호/HTTPS 인증으로 우회하지 않습니다. `IdentitiesOnly`, 지정한 키, host key 검증을 사용하고 매 전송마다 GitHub 계정을 확인합니다.
4. 원격 주소는 `git@github.com:JaehongLIM2/alarm_program.git`만 허용합니다. 기존 다른 origin은 덮어쓰지 않습니다.
5. 커밋 훅은 실제 author와 committer가 지정된 개인 계정과 메일인지 확인합니다. 환경 변수로 다른 작성자를 지정한 경우도 거부합니다.
6. 푸시 훅은 목적지와 새 커밋의 작성자/커미터를 검사하고 이력 덮어쓰기, 브랜치 삭제, 태그 푸시를 거부합니다. SSH 환경 변수로 전송을 교체한 경우도 거부합니다.
7. 점검한 소스를 커밋한 뒤 강제 옵션 없이 main을 푸시하고, 원격 main의 SHA가 로컬 HEAD와 같은지 확인합니다. 이 검증까지 끝나야 성공으로 표시합니다.

로컬 훅은 실수 방지 장치입니다. 사용자가 의도적으로 `--no-verify`를 쓰거나 설정·훅을 수정하는 행위까지 막는 서버 측 접근 제어는 아닙니다. 새 clone에서는 로컬 설정이 복사되지 않으므로 설정 스크립트를 다시 실행해야 합니다.

## 실행

일반 Windows 사용자로 프로젝트 폴더에서 다음을 실행합니다. 관리자 권한은 필요하지 않습니다.

```powershell
.\scripts\publish-personal.cmd
```

현재 작업 폴더에는 사용자 제공 이메일을 담은 무시되는 로컬 파일이 준비되어 있습니다. 다른 clone에서는 다음처럼 이메일을 지정합니다.

```powershell
.\scripts\publish-personal.cmd -Email "<GitHub commit email>"
```

기본 개인 키 파일명은 사용자 프로필 아래 `.ssh/id_ed25519_personal`입니다. 다른 파일이면 `-KeyPath`로 지정합니다. 키 내용이나 토큰을 소스에 넣지 마세요. SSH host key가 등록되지 않았거나 개인 키를 비대화형으로 사용할 수 없으면 중단하며, 다른 계정으로 재시도하지 않습니다. 원격 저장소가 이미 초기화되어 이력이 다르면 이력을 확인하고 합치기 전에는 게시하지 않습니다.

소유자가 다른 `.git`에 대한 임시 신뢰는 게시 스크립트 실행 중에만 유효합니다. 일반 PowerShell의 `git` 명령에 소유권 오류가 계속 나타나면 이 게시 스크립트를 통해 커밋·푸시하세요. 전역 `safe.directory`를 바꾸거나 소유권을 자동 변경하지 않습니다.

점검만 실행하려면:

```powershell
powershell.exe -NoProfile -NonInteractive -ExecutionPolicy Bypass -File scripts/Test-RepositorySecurity.ps1
```

`ExecutionPolicy Bypass`는 이 프로세스의 로컬 스크립트 실행에만 적용합니다. 시스템 실행 정책, 파일 접근 권한, 네트워크 권한을 변경하지 않습니다.

## 권한이 제한된 실행 환경

Git 메타데이터 쓰기, 개인 SSH 키 사용, GitHub 연결이 제한된 샌드박스에서는 게시할 수 없습니다. 필요한 실행 권한이 허용된 환경에서 스크립트를 실행해야 합니다. 다른 계정으로 대체하거나 강제 푸시하지 않습니다. SSH 보조 스크립트는 Git이 전송 환경을 정리하는 경우에도 해당 체크아웃의 `.git/config` 파일만 명시적으로 읽으며, 전역 인증 설정으로 대체하지 않습니다.
